# Phase V-B Revision (`phase5b`)

## Experiment Revision Identifier

All artifacts generated by the corrected Phase V benchmark carry
`phase_variant = "phase5b"` in their frozen configuration.

## Incompatibility with Historical Phase V-A Results

**Phase V-B results are NOT bitwise comparable to Phase V-A results.**

The original Phase V benchmark (`phase5a`) used Python's built-in `hash()`
function to deterministically select scenario pairs, triples, family-case pool
seeds, and policy-specific seed offsets.  Python's `hash()` is randomised
per-process via the `PYTHONHASHSEED` environment variable, so:

- Running the same code under different `PYTHONHASHSEED` values produced
  **different** scenario selections and **different** benchmark outcomes.
- Results stored under `artifacts/phase5/` were generated under a specific
  `PYTHONHASHSEED` that cannot be recovered; they are therefore effectively
  non-reproducible.

Phase V-B replaces every experiment-affecting `hash()` call with a stable
SHA-256 helper (`_stable_hash`) that uses domain separation and length-prefixed
canonical encoding.  The new scheme is deterministic across all Python processes,
regardless of `PYTHONHASHSEED`.

Because the selection scheme changed, **historical Phase V-A generated rows are
not comparable** to Phase V-B rows.  Do not mix artifacts from the two revisions
without explicit reconciliation.

## Three-Pool Split Design

Phase V-B introduces three demonstrably non-overlapping experiment pools:

| CLI `--split` argument | Pool name              | Purpose                                          |
|------------------------|------------------------|--------------------------------------------------|
| `development`          | Development            | Active iteration and development experiments     |
| `validation`           | Selection-validation   | Provisional candidate selection                  |
| `test`                 | Final-validation       | **LOCKED** – requires `--unlock-test` flag       |

### Disjointness Guarantees

The three pools have **pairwise disjoint** mechanism IDs, pair IDs, and triple
IDs.  This is verified by automated tests in
`tests/qrtc_benchmark/test_phase5b_pools.py`.

**Development mechanisms** (18 total):
- V1: gate_amplitude_clamp, boat_amplitude_compression, river_gaussian_dispersion,
  distributed_thermal_attenuation, witness_fixed_integration, jurisdiction_threshold_error
- V2–V4: pair_seen_m1–m4, triple_seen_m1–m4, unknown_seen_m1–m4

**Selection-validation mechanisms** (9 total):
- V1: gate_state_dropout, boat_nonlinear_temporal_recoding, river_multipath_echo
- V2–V4: pair_ood_m1–m2, triple_ood_m1–m2, unknown_ood_m1–m2

**Final-validation mechanisms** (9 total):
- V1: distributed_cross_channel_delay, witness_adaptive_saturation, jurisdiction_context_boundary
- V2–V4: pair_ood_m3–m4, triple_ood_m3–m4, unknown_ood_m3–m4

**Development pairs**: FG+FW, FR+FJ, FD+FW, FB+FR, FG+FJ, FB+FD

**Selection-validation pairs**: FG+FD, FG+FR, FB+FJ

**Final-validation pairs**: FR+FW, FD+FJ, FB+FW

**Development triples**: FG+FW+FJ, FB+FR+FJ, FG+FD+FW, FB+FR+FD

**Selection-validation triples**: FG+FR+FD, FB+FW+FJ, FG+FB+FW, FR+FD+FJ

**Final-validation triples**: FB+FR+FW, FR+FW+FD, FR+FW+FJ, FW+FD+FJ

The strong holdout invariant is preserved: constituent pair projections of the
final-validation triples do not include any selection-validation pair.

### Final-Validation Lock

The final-validation pool (`--split test`) is locked by default.  Attempting to
run it without `--unlock-test` raises a `PermissionError`.  **Do not unlock
final validation in this PR.**  Final validation must only be executed after the
selection-validation results have been reviewed and a provisional primary
candidate has been identified.

## Historical Artifact Preservation

Artifacts under `artifacts/phase4b/` and `artifacts/phase5/` (including
`development-v2/`) are **preserved byte-for-byte** and must not be overwritten,
regenerated, or deleted.  Phase V-B smoke/test artifacts are written only to
temporary directories during testing.

## Controller Selection Status

No controller-selection result or validation claim is produced by this PR.
The provisional primary candidate policy remains `qrtc`.  Formal selection
requires running the final-validation split with the unlock flag, which is
explicitly prohibited in this PR.
